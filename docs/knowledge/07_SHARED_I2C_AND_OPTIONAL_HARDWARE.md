# 共享 I²C 与可选硬件降级

## 总线基线

GPIO15/16 是板载 ES8311 的 I²C 总线，PCF8563 使用地址 `0x51` 与 ES8311 `0x18` 共存。当前代码由 `I2cBusService` 统一调用 `Wire.begin(SDA=16, SCL=15, 400kHz)`；每个器件的初始化和轮询必须有自己的状态，不应让可选模块成为整个系统的启动依赖。

## 可选硬件原则

- 模块不存在、NACK、VL 置位或字段非法时，屏幕、USB、音频和其它实验仍应工作。
- 初始化失败低频重试，不在主循环中忙等，也不持续刷日志。
- 读回数据必须做范围和格式校验，不能把 2000 年等默认日期当成有效时间。
- 运行中接入模块后，先完成完整探测和校验，再把状态切换为 ready。

## 接线检查

- 确认 3.3V 兼容性。
- 记录模块自带的上拉电阻，避免并联后阻值过低。
- 不可充电 CR2032 不得接入带充电回路的 RTC 模块。
- 共享总线出现锁死时，先断开新增模块验证基础器件是否仍稳定。

PCF8563 的时间寄存器访问必须一次完成 `0x02`（VL_seconds）到 `0x08`（Years）的整块读写；`VL=1` 表示时钟完整性无法保证，`STOP=1` 表示 RTC 时钟已停止。应用层应显示降级状态，不能把这类数据当成可信时间。

## PCF8563 与网络时间的分层

- 启动时优先读取 RTC；Wi-Fi 连接后用 SNTP 校时，再把网络时间整块写回 PCF8563。
- 若 RTC 不存在或接触不良，本次开机完成一次 SNTP 后仍可由 ESP32 系统时钟提供时间；重启后没有 RTC 就必须再次联网校时。
- UI 不应只看“RTC 是否 ready”决定是否显示时间，而应显示有效时间源：`NTP → PCF8563 → unavailable`。同时单独报告 RTC 状态，避免把网络时间误说成电池时钟。

## 接触不良与运行中恢复

可选 I²C 外设不能只在启动时探测一次。PCF8563 实测在插座未焊牢时出现 `ready → io_error → ready`；低频重试可以在模块重新接触后恢复，而不阻塞 LVGL、USB、Wi-Fi 或音频。建议：

- ready 状态按秒读取；NACK/读错误后退避到约 2 秒；not found 约 5 秒重探测。
- 只在状态变化或错误计数变化时打印日志，不在每次轮询失败时刷屏。
- 状态快照保留 `detected`、`errorCount`、`VL`、`STOP` 和有效时间源，方便区分“模块不存在”和“字段不可信”。

## 最小真机检查

1. 先执行 `i2c scan`：本开发板正常时应看到 ES8311 `0x18`；PCF8563 接通后还应看到 `0x51`。
2. 执行 `time status`，检查 `state=ready`、`vl=0`、`stop=0`、`errors=0`，并确认 `source=rtc` 或联网后的 `source=ntp`。
3. 断开/恢复模块时观察是否只发生一次状态切换，并确认时间页面仍能显示 NTP 或 RTC 回退时间。
4. 焊接后再做冷启动无网络和断电电池保持测试；这两项不能用一次在线启动代替。
