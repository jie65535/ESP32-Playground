# ES8311 音频方向和功放使能

## 已验证结论

- ES8311 控制总线使用 GPIO15/16 I²C。
- ESP32 播放数据方向是 GPIO8（DAC DATA）。
- GPIO6 是麦克风 ADC DATA，误当成播放脚会完全无声。
- GPIO1 是功放使能，当前板卡为低电平使能。
- 8kHz、1kHz、双声道简单方波可作为最小播放测试。
- GPIO6 麦克风已用 ES8311 模拟 MIC/ADC 配置和 8 kHz I²S RX 实测采到非零 PCM；USB 导出时使用 mono PCM16LE WAV。
- 麦克风和播放共用 I²S 控制器时，TX 播放链保持由音频任务拥有；RX/DSP 只在麦克风页、显式耳返或 USB 录音期间运行，页面只读快照或提交请求。
- 输入增益、降噪、VAD、人声 AGC 和播放音量是不同阶段：输入增益会同时抬高人声与模拟底噪，降噪压低停顿期和弱背景，VAD 决定是否是语音，AGC 只放大已判定语音，播放音量只改变 DAC/功放响度。
- 当前轻量降噪使用约 100 Hz 固定点高通、平滑噪声底估计和 downward expander；它不使用 FFT/模型，关闭时完全旁路，也不能替代强噪声中的频谱降噪。
- 当前人声增强使用 `libfvad` 的 WebRTC VAD：8 kHz、20 ms、mode 3，连续 2 帧确认并增加 120 ms 退出 hangover，再进入最大 4 倍 AGC 和峰值限幅。它比 RMS 门限更能拒绝音乐瞬态，但没有声源参考，不能区分真人、录音人声或歌曲中的歌声。
- AEC 与降噪不同：AEC 必须使用喇叭 PCM 参考估计声学回声路径；近距离耳返防啸叫还需要限制环路增益、限幅或独立反馈抑制。

## 推荐实验顺序

1. 先只初始化 I²C 和编解码器，确认地址响应。
2. 再配置 I²S 时钟和 GPIO8 播放方向。
3. 拉低 GPIO1 使能功放。
4. 从静音 PCM 开始，再逐步提高数字幅度和编解码器音量。
5. 试听爆音、失真、连续播放温升和复位后的静音状态。
6. 麦克风先看 RMS/Peak 和静音基线，再用人声检查增益、削波、直流偏置和清晰度。

## 常见错误

- 把 ADC 输入脚当成 DAC 输出脚。
- 功放 EN 电平反了，导致 I²S 有数据但扬声器无声。
- 一上来播放大幅度方波，造成爆音或误判硬件故障。
- 忽略 I²C 总线上的其它器件和地址冲突。
- 在板载扬声器附近高音量开启耳返，可能形成声学反馈；耳返应默认关闭并限制增益。
- 把噪声门或降噪误当成 AEC，无法阻止喇叭播放内容再次进入麦克风。
