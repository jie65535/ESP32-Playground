# Flash 持久化、CRC 与栈内存

## 持久化经验

需要掉电恢复的循环数据应具备：版本、递增序号、记录数、CRC，以及至少两个可切换槽位。写入新槽成功后再更新有效标记，启动时选择最新且 CRC 正确的槽。

## 写入频率

只在状态边沿、明确维护操作或启动对账时写 Flash；不要每秒把动态计时写入 Flash。持续时间可以在 RAM 中由单调时钟计算。

## 栈内存事故

大数组、双槽缓存和一次性启动交接对象放进 `loopTask` 栈，可能在编译正常后上板崩溃或重启。更安全的方式是：

- 大缓冲放堆或 PSRAM。
- 启动交接对象放静态存储，或者显式管理生命周期。
- 分配失败必须可观察并降级。
- 在日志中记录剩余堆和 PSRAM，必要时检查高水位。

## 适用边界

Playground 当前屏幕实验不需要历史存储，但后续 Wi-Fi 缓存、音频缓冲、截图和实验数据都应遵守同样的内存纪律。
