# 实验 020：PGOS 超级马里奥 1-1

> 日期：2026-07-21
> 状态：第一关数据、动态对象和全图 maptest 已完成；本轮相机回卷、跳跃高度、相邻箱命中、摇杆中心过滤和死亡诊断已通过主机测试及构建，并已烧录 COM3，等待用户真机复测

> 后续：本记录保留为 1-1 原型和性能优化的历史基线。32 关战役、紧凑地图格式及新增机制见
> [实验 021](021_platformer_campaign.md)。

## 目标

验证当前 ESP32-S3 / PGOS 基座是否能承载经典横版平台游戏的第一关闭环：固定步进、碰撞、摄像机卷轴、连续手柄输入、砖块/问号奖励、敌人、旗杆流程、事件反馈和单面绘制。

## 当前实现

- 纯 C++ `PlatformerEngine` 不依赖 Arduino、LVGL 或 NVS，使用
  [Mario-Level-1](https://github.com/justinmeister/Mario-Level-1) 参考工程的原版
  第一关坐标和测量碰撞矩形。
- 关卡已经从引擎内硬编码改为 `PlatformerLevelDefinition`：当前对齐该工程的
  3392×224 背景条带、四段地面、6 个管道、楼梯/城堡碰撞矩形，以及 31 个普通砖和
  12 个问号箱坐标。
- `PlatformerApp` 使用单一 `RenderSurface`，不为瓦片、玩家、敌人或奖励动画创建 LVGL 子对象。
- 游戏逻辑使用 8ms 固定步进；主循环单轮最多补算 6 步，沿用 Breakout 的有界追赶策略。
- 玩家水平移动使用加速/减速和最大速度；跳跃支持按住延长、提前释放缩短、约 80ms 离地宽容和约 100ms 提前输入缓存。
- 首轮实体手柄复测发现普通跳跃净高度低于 63px 高管道、短按不易命中低层砖块；现将普通/快速初速度调整为 244/264px/s，并给跳跃前 120ms 最小抬升。主机测试确认短按可命中低层箱、长按可越过最高中段管道。
- 跳跃参数按参考工程的 `JUMP_VEL=-10`、`JUMP_GRAVITY=.31`、`GRAVITY=1.01` 换算到设备坐标；
  更新顺序也保持“先按当前速度移动，再施加下一步重力”，释放按键不额外截断上升速度，避免点按和
  长按高度偏离原版。
- 玩家支持左/右移动、跳跃、重力、平台碰撞、摄像机卷轴和终点旗帜；背景使用原项目的
  预合成关卡图，静态地面、管道和楼梯不再由另一份样例地图重画。
- 相机使用 80px/约 100px 的双向跟随区间；回走时镜头会回卷，地图起点和终点仍按世界边界夹紧。
- 敌人按原项目的检查点分组位置转换到设备坐标；当前实现进一步改为在触发检查点时按
  `viewport.right + 60px * group_index` 动态生成，避免相机位置变化造成少数敌人世界坐标错位。
  敌人碰撞盒直接贴合转换后的地面，避免 Koopa 浮空或卡在错误高度。
- Xbox D-pad/左摇杆提供连续移动，A 或 USB `ok` 跳跃，X/USB `quick drop` 语义暂停，B/Home 保留系统返回语义。
- Platformer 在进入应用和手柄重连时记录摇杆中心，并以 144/88 的进入/退出迟滞过滤中心漂移，避免静止时反复切换 idle/run；D-pad 仍是直接数字输入。
- 真机继续出现的静止“鬼畜”最终定位为引擎落地标志隔步翻转：`vy=0` 时旧逻辑仍先清除 `grounded`，渲染因此在 idle/jump 间切换。现仅在脚下仍有实体支撑时保持落地，走出坑口仍会立即进入下落。
- 金币、踩踏、死亡和过关复用现有反馈音和手柄震动接口；完整背景音乐暂不加入。
- 死亡状态区分 `TIME UP`、`ENEMY HIT` 和 `FELL`，提示不遮挡死亡跳跃。静止时敌人仍会自主接近，关卡计时也会继续，提示用于确认实际死因。
- 关卡逻辑、碰撞和输入仍由 PGOS 自己实现；本轮按用户指定的学习用途，从本地参考工程
  选取少量 16×16 图像帧做离线转换，不把参考工程运行时依赖带进固件。
- `tools/convert_platformer_assets.py` 继续转换动态精灵；新增
  `tools/convert_mario_level_background.py` 将原项目的 `level_1.png` 转为 11 个不透明
  RGB565 条带，设备端不依赖 PNG/GIF/JSON。
- `PixelSpriteRenderer` 普通精灵走 LVGL 单图像任务，镜像/缩放才回退到同色水平段；
  `PixelSprite` 只保留一份 RGB565+A8 打包数据，回退路径直接从同一数据读取像素和透明度，
  不再为每帧重复保存 `pixels`/`alpha` 平面。资源转换和绘制接口均与游戏逻辑解耦。
- 关卡对象表包含 12 个可碰撞 CoinBox、普通砖、多金币砖、星星砖和隐藏 1UP 箱：从下方顶到
  未开启箱子会按原版数据产生金币、蘑菇/火花、星星或 1UP；金币和奖励实体由固定数组承载，
  不在运行中分配内存。第一关没有预先散落的自由金币，金币只在顶箱/多金币砖后生成。
- 普通砖与问号箱已拆开处理：小 Mario 顶普通砖只触发顶撞而保持砖块外观，大 Mario 顶普通砖
  会移除碰撞并隐藏砖块；问号箱会变为空箱。多金币砖有 6 次使用次数，星星砖和隐藏 1UP
  箱按参考工程的检查点/坐标工作，砖块碎片、金币弹出和道具动画均已接入。
- 当头部同时跨到相邻砖和问号箱时，命中对象选择水平覆盖最大、中心最近的一项，不再依赖对象数组顺序。
- 原背景条带包含静态砖图案；大 Mario 破砖后现由动态层以关卡天空色覆盖对应 16×16 区域，避免碰撞已删除却露出一块无法再破坏的“假砖”。
- 蘑菇被玩家吃到后会切换到大 Mario 状态：碰撞盒增高、脚底保持在原地，并使用参考工程的
  16×32 大 Mario 离线精灵帧。
- 敌人定义仍由固定数组承载，但出生位置不再只依赖预计算的固定 x：Goomba 和 Koopa 共用巡逻、
  碰撞和踩踏状态机；Koopa 仅在外观与碰撞尺寸上使用自己的数据，后续可在同一池中增加缩壳/踢壳状态。
- 同一物理步跨到两个敌人头顶时，碰撞循环固定使用步首的下落状态，先结算所有踩踏再只施加一次反弹，不会因第一个踩踏提前把 `vy` 改为负值而让第二个敌人触发受伤。
- Fire Mario 的火球池保持同时最多 2 发；移除“历史槽位数达到 2 就直接返回”的错误前置判断后，飞出屏幕的失效槽位可持续复用，不会发射几次后永久失效。
- 首轮精灵版真机出现约 1–2 FPS，原因是 `PixelSpriteRenderer` 把每个精灵拆成大量同色水平段，
  摄像机移动又会让整面重绘。优化版为每帧附加连续的 LVGL RGB565A8 数据，普通精灵/地砖
  只提交一个图像任务；镜像或缩放时才回退到水平段路径。
- 精灵描述符环形缓存按单帧实际使用量从 96 项收敛到 32 项；当前单帧少于 24 种图像，
  保留余量的同时释放 2048 bytes 常驻 RAM。1-1 没有地图预置金币，因此也移除了始终为空的
  32 项自由金币池；CoinBox、多金币砖、金币计数和弹出动画继续走现有奖励路径。
- Snake、Tetris、Breakout、Blackjack 和 Platformer 的矩形/文字绘制已统一进入 `CanvasDraw`；
  顶部 HUD、按钮和覆盖层都按字体实际行高使用同一套垂直居中规则。
- 原版背景条带已替换 PGOS 早期的绿色几何山丘和错误 60 列样例布局；当前首屏应只出现
  原版的天空、云朵、山丘、灌木和地面，第一只问号箱位于首屏右侧，管道和普通砖按真实
  关卡距离出现。砖块相邻坐标已按转换后的设备像素校正，避免 1px 浮点取整缝隙。
- USB `platformer maptest` 固定 Mario 和所有敌人，`platformer mapnext` 每次将相机推进 256px；
  `tools/capture_platformer_map.py` 自动抓取 13 段并拼接 3392px 全地图，便于检查敌人出生点、
  管道、坑、砖块、旗杆和城堡的连续性。maptest 保持原版静态画面，不预先显示尚未被顶出的金币/道具。

## 渲染边界

`RenderSurface` 先把“一个 App 只拥有一个游戏绘制面”的边界固化下来；当前 Platformer 仍在摄像机移动时整面失效，因此稳定目标是约 30 FPS 画面 + 60Hz 级别逻辑。后续可以在该边界内增加脏矩形、精灵缓存和 PSRAM framebuffer，不需要让每个游戏对象重新进入 LVGL 对象树。

## 验证

```text
python -m unittest discover -s tools/tests -p "test_*.py"
pio run -e playground
pio run -e playground -t upload --upload-port COM3
python tools/capture_platformer_map.py --port COM3
```

2026-07-21 主机测试共 35 项通过，覆盖落地、短按/长按跳跃、最高中段管道所需净高度、横向移动、摄像机双向滚动、相邻砖块/问号箱命中、三种死亡原因、暂停冻结、
CoinBox 金币/蘑菇、6 金币砖、普通砖碎片、星星、隐藏 1UP、大 Mario/火花状态、敌人池、
检查点生成、防止敌人卡进管道、旗杆流程和 maptest 全图平移；资源测试覆盖 RGB565 转换、
透明色、帧数量、尺寸、打包数据长度、背景分块和全图拼接边界；手柄策略测试另覆盖带中心偏移的轴输入和进入/退出迟滞。提交前清理移除了运行时未使用的
2968-byte tile cache、2048-byte 多余精灵描述符缓存和 192-byte 空自由金币池；动态精灵资源
去重后，本轮烧录固件资源为 RAM 83,080 / 327,680 bytes、Flash 3,401,369 / 6,553,600 bytes。
本轮修正版已烧录 COM3 并通过写入校验；此前 maptest 重新生成
`captures/platformer/maptest/platformer-map-panorama.png`；拼接工具已修正末尾 64px 黑边并增加瞬时截图失败重试。

自动截图已确认：全图 13 段可拼接，敌人出生位置不再嵌入管道，旗杆底部补齐最后一格，
标题/HUD 条带文字垂直居中；另以分类截图复核 Snake 和 Blackjack，确认共享 `CanvasDraw`
在现有自绘游戏中保持同一居中结果。由于当前没有开启实体手柄，模拟量跑步、变速、连续跳跃、
手柄震动和长时间稳定性不作“已验证”结论。

本轮最终固件再次通过 35 项主机测试；Platformer 原生套件新增连续 240 个静止步保持落地、坑口失去支撑后下落、双敌同踩、火球失效槽连续 5 轮复用和同时两发上限。最终固件已烧录 COM3；USB 启动游戏后相隔 1.5 秒抓取两帧，Mario 30×28 区域差异像素为 0，确认静止动画不再抽搐。USB 跳跃和左右相机回卷截图正常；破砖视觉、Fire Mario 连射和实体手柄双敌同踩仍需下一次有手柄时做最终真机确认。
