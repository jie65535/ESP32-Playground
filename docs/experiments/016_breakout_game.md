# 实验 016：PGOS 打砖块小游戏

## 目标

在贪吃蛇和俄罗斯方块已经建立的独立游戏绘制、统一输入和分数持久化边界上，实现一款带连续运动与碰撞检测的打砖块游戏，验证固定步进物理在当前 LVGL/DMA 主循环中的可行性。

## 当前实现

- App：`BreakoutApp`，使用状态栏下方 320×218 的单一 LVGL 自绘面，不直接访问 TFT、SPI 或 flush 回调。
- 玩法：3 条命、3 个关卡；第二、三关加入空缺布局和双耐久砖块，逐关缩短挡板并提高发球速度。
- 操作：D-pad 左右或左摇杆连续移动挡板；A 开始、发球、暂停、继续和重开；B/Home 沿用系统级返回桌面语义。
- 物理：8ms 固定步进，每轮最多补算 6 步，单轮累计时间限制为 48ms；球速逐步增加并在 178 px/s 封顶，避免低帧率下穿透砖块。
- 反弹：挡板命中位置决定主要反弹角度，移动方向提供少量修正；近中心命中保留最小水平速度，避免球长时间垂直往返。
- 计分：砖块行、关卡、耐久和连续击碎共同决定分数；挡板接球或丢球会重置连击，过关按当前关卡和剩余生命追加奖励。
- 反馈：击中/击碎砖块、挡板反弹、丢球和过关使用现有 `AudioService`；丢球与过关在手柄连接时请求短震动。
- 效果：每次击碎砖块从定长 30 元素粒子池发射 5 个碎片，不创建 LVGL 子对象，也不在游戏循环中动态分配内存。
- 持久化：`BreakoutScoreService` 使用独立 `pgos_breakout` NVS namespace 保存 Top 5；每局只入榜一次，避免 Game Over 和离开页面重复写入同一成绩。

> 2026-07-20：实验 017 将同构实现合并为 `GameScoreService`，上述
> `pgos_breakout` namespace、schema=1 和每局一次入榜规则保持不变。
- 入口：Launcher 的 Breakout 卡片、USB/TCP `page breakout` 或 `game breakout`，以及 `tools/playground_console.py` 的 `B` 快捷键。

- `page breakout` 可直达标题页；320×240 shadow framebuffer 截图确认状态栏、HUD、六色砖墙、Top 5、球、挡板和标题层完整，无裁切或重叠。
- `ok` 启动后球在真机持续推进，可击碎砖块并更新分数；运行态截图观察到砖块缺口和分数变化。
- 再次 `ok` 可显示暂停层；暂停后连续发送三次 `left`，挡板保持原位，确认暂停期间离散输入不会修改游戏状态。

## 待真机验证

1. 从 Launcher 手动滚动到 Breakout 并进入，Xbox A/B/Home 的开始、暂停、重开和退出语义正确。
2. Xbox D-pad 与左摇杆连续控制平滑，摇杆回中后挡板停止；USB/TCP 左右命令在运行和待发球状态可单步移动。
3. 长时间观察球在边墙、顶墙、挡板边缘和砖块角落不会穿透、粘连或连续错误计分。
4. 完整玩通三关，确认双耐久提示、生命扣除、连击、过关奖励、胜利和断电后的 Top 5 持久化正确。
5. 现场确认碎裂效果、音效和震动观感，并验证不会造成 LCD DMA 卡顿、BLE 断连或镜像异常。

## 资源与边界

- 游戏状态全部是 `BreakoutApp` 的固定大小成员；没有新增 framebuffer、FreeRTOS 任务或后台服务循环。
- 分数只在 Game Over、胜利或离开 App 时写入 NVS，不在击砖或物理步进中写 Flash。
- 当前碰撞使用圆与轴对齐矩形检测，优先保证小屏经典玩法的稳定性；旋转物体、任意形状砖块和多球留待独立实验。
