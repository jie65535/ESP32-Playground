# 实验 022：Platformer 参考行为对齐

> 日期：2026-07-22；2026-07-23 完成 COM3 烧录冒烟
> 状态：代码层验收与 COM3 烧录通过；等待实体 Xbox 手柄最终验收

## 目标与事实来源

以 [Super-Mario-Bros](https://github.com/Gold872/Super-Mario-Bros) 参考工程的提交
`609c5af217abf6eb55d3eb594df4db76cfb0c90c` 为玩法逻辑唯一事实来源。参考
工程采用 MIT License，Copyright (c) 2022 Gold87。PGOS 不照搬 SDL2/ECS
架构，但玩家可观察到的规则、状态顺序、数值和事件时点应与该提交一致。

本实验中的“对齐”指坐标归一化后的黑盒行为等价，不表示与 NES 原版或其它
Mario 工程等价。参考提交的正常玩法行为优先于 PGOS 早期从其它样例引入的
手感调整。

## 允许差异白名单

- 320x240 LCD、22px PGOS 状态栏和 320x218 游戏区域。
- RGB565/PSRAM framebuffer、40 行 LCD DMA、地图 RLE 和调色板索引图块。
- 固定实体池、有界队列和不在运行时分配大型对象的嵌入式资源约束。
- Xbox/USB 输入映射、PGOS App 生命周期和 NVS 继续进度。
- 只影响呈现、不改变玩法状态的 HUD 排版、音色和震动强度。
- 已记录的参考数据缺失或会导致越界、崩溃、资源耗尽的问题修复。

白名单外的差异必须进入下方清单；不能以“手感优化”或“已有实现可用”为由
静默保留。

## 验证策略

日常验证不上传固件、不探测 COM 端口、不抓取设备截图：

1. 以固定种子和脚本输入运行纯 C++ 引擎。
2. 对照参考源码的 60Hz 系统顺序，检查逐逻辑帧的位置、速度、状态和事件。
3. 坐标按参考 32px 逻辑砖到设备 16px 砖归一化；关键位置容差不超过 1px，
   关键时序容差不超过一个参考逻辑帧。
4. 每个确认差异先补最小回归测试，再修改共享机制。
5. 阶段末运行全部 Python 测试及 `pio run -e playground`，但不执行 upload。

纯代码验收通过后，状态只能更新为“等待真机验证”。用户连接开发板并以实体
Xbox 手柄确认操控、DMA 帧 pacing、音效/震动和长期稳定性之前，本实验和对应
goal 均不能标记完成。

## 参考系统顺序

参考 `GameScene` 按以下顺序注册系统，`World::tick()` 严格按注册顺序执行，并在
每个系统后清理销毁队列：

1. `MapSystem`
2. `PhysicsSystem`
3. `PlayerSystem`
4. `AnimationSystem`
5. `EnemySystem`
6. `CollectibleSystem`
7. `WarpSystem`
8. `FlagSystem`
9. `CallbackSystem`
10. `ScoreSystem`
11. `SoundSystem`
12. `RenderSystem`

因此碰撞标记由 Physics 产生、Player/Enemy/Collectible 消费并清理；动画、回调
和分数又分别晚于玩家及敌人逻辑。仅复制最终常量而改变这个消费顺序不算等价。

| 玩家碰撞 | 对齐方向 roundness、推离上限、蹲姿一格高碰撞盒和脚底锚定；窄井、低通道、顶砖与落地有确定性场景 |
| 摄像机 | 对齐参考单向横向推进、冻结、区域摄像机和传送后的最小边界；设备坐标统一为参考坐标的 1/2 |
| 敌人 | Goomba、Koopa/龟壳、Paratroopa、Piranha、Blooper、Lakitu/Spiny、Hammer Bro、Bowser、Cheep Cheep、Buzzy Beetle、Bullet Bill、Lava Bubble 均按参考状态、回调和帧周期处理；普通敌人相撞的有序转向也保留参考 ECS 的跨帧顺序 |
| 敌人图层 | 修复未知参考帧默认生成 Goomba 的问题；参考 `default: break` 的动画帧/占位格现在不会创建实体，静态预览也复用同一判定；关卡载入时按参考一次性创建全部 CSV 敌人，8-4 回环不再清空实体状态 |
| 道具与投射物 | 对齐蘑菇/1UP 转向、星星反弹、花的静止、火球首帧/反弹/爆炸、敌人过滤和固定池复用 |
| 地图交互 | 对齐 8 帧砖块 bump、延后一帧碎砖、四块碎屑、上方敌人击杀、隐藏砖、问号块、多金币砖和浮动分数 |
| 平台与危险物 | 对齐往复/循环/重力平台、高斯速度曲线、滑轮解体、云平台落脚后启动、同步炮台、预置 Bullet Bill、火焰棒、弹簧及离屏规则 |
| Warp 与藤蔓 | 对齐零宽触发线、入管/出管阈值、区域与跨关命令序列、3 秒跨关加载；区域传送会按参考收回并重置外露食人花 |
| 旗杆与城堡 | 对齐旗帜和 Mario 下滑、换边、0.6 秒等待、砖块推离、自动走到真实城堡碰撞、逐帧时间奖励及隐藏时点 |
| Bowser 桥 | 对齐冻结、每 5 帧拆桥、Bowser 回调继续执行、坠落等待、Mario 自动行走和 5 秒切关 |
| 变身与死亡 | 对齐蘑菇/花序列、受伤缩小、闪烁、星星最后保护帧、死亡抛物线、180 帧回调和 180 帧关卡加载 |
| 分数与进度 | 对齐踩敌/龟壳/火球/道具分数、金币不自动换命、1UP、每 30 帧减 1 的关卡时间和 NVS 继续点 |
| 动画与事件 | 玩家、每个敌人、道具/效果、可见地图砖和每段火焰棒分别持有参考动画时钟；BlockHit/CoinCollected、持锤、Lakitu 入云、敌人翻转、上升金币、碎屑、暂停和脚本事件均按系统顺序分离 |

逆向完成审计按参考 `MapSystem` 的全部特殊方块和敌人分支，以及 Physics、Player、
Enemy、Callback、Score、CommandScheduler 的跨系统顺序逐项复核。除食人花离屏
运动、区域水管收花、飞鱼顶点踩踏和未知敌人帧误生成为 Goomba 外，还修复了：

- 炮台统一 300 帧周期、可见性判定、环境子弹贴图和生成帧；预置 Bullet Bill
  按参考在首个 Physics 帧离屏销毁，首屏个体只播放一次出现音。
- 云平台不是静态实心砖；Mario 首次落脚后的 Callback 才赋予速度，并从下一帧
  开始移动且不携带 Mario。
- Lakitu 的 Timer 离屏仍计时，已开始的 0.75 秒命令离屏和暂停仍继续；入云期间
  实体与贴图均缩成一格，Spiny 从恢复后的顶部以参考速度生成且本帧不参加 Physics。
- 普通敌人碰撞恢复参考的有序转向；Spiny/Bullet Bill 不再被龟壳的反向遍历误杀。
- 关卡时间移到 ScoreSystem 等价的帧尾；死亡或碰旗当帧不多扣一秒，进入水管当帧
  仍计时。受伤闪烁的最后一帧继续免伤，帧结束后才恢复可见和可碰撞。
- 暂停继续执行已排队的 Lakitu/Hammer Bro 全局命令，但冻结 Physics、Animation、
  Timer 和关卡时间；Hammer Bro 离屏持锤期间不会被固定池提前回收。
- Bowser 每次攻击固定消耗两次随机数，锤子计划数恢复 6-10；同时保留参考中
  `Callback(0)` 先减为 -1 导致第 0 把不发射的实际 5-9 把结果。
- 32 关的静态敌人峰值为 8-1 的 57 个，设备池预留 57 个关卡实体和 23 个动态
  实体槽；炮弹和 Spiny 复用失效槽，8-4 传送保留仍存在敌人的位置与状态。
- 敌人出生点逐格核对 CSV 行列顺序：参考编号 39/71 使用右移半格，飞鱼编号
  498 按出生格背景 186 判定水下/飞跃形态，飞跃形态下移一格且保持实例语义。

## 自动验证结果

  敌人、道具、脚本、动画、事件和关卡切换。

随后按用户明确要求执行真机烧录冒烟：

- `pio run -e playground -t upload --upload-port COM3`：成功；ESP32-S3、16MB

- USB `status` 返回 `app=Super Mario heap=52916 psram=7417796`，确认 PGOS 与

实体 Xbox 初步复测中，火焰马里奥曾出现一次无法拾取金币和顶方块的现象，但

同时验证同一状态接触并站上 1-2 两块下降平台不会在接触帧死亡。下降平台首次
看似触碰即死的现象经再次复测确认是关卡时间耗尽，平台碰撞本身正常。

上述结果代表代码层没有保留已知的白名单外玩法差异，不代表已经完成真机验收。
