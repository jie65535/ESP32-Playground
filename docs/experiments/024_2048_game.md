# 实验记录：PGOS 2048 动画小游戏

> 日期：2026-07-24
> 状态：主机规则、离线布局、目标板构建和 COM3 初步真机验收通过

## 目标

在现有 PGOS Games 菜单中加入一款按键友好的 2048。它保持游戏 App 的单一 LVGL 自绘面，不创建 16 个 LVGL 子对象，也不让规则层依赖 Arduino、LVGL 或硬件服务。

## 实现范围

- `src/games/Game2048Engine.*`：4×4 规则引擎，纯 C++。
  - 每次有效移动只生成一个 2/4 方块，概率为 90%/10%。
  - 一次移动中每个方块最多合并一次，四个相同方块按两次合并处理。
  - 记录移动/合并的来源和目标格，供 App 做滑动动画。
  - 2048 达成后继续游戏；无空格且无相邻同值方块时判负。
- `src/apps/Game2048App.*`：320×218 前台画面。
  - 4 格内边距、暖色分级方块、深色 Slate 背景、分数卡片和圆角面板。
  - 145ms ease-out 滑动；合并方块在末段弹性放大后回落；新方块从小到大出现；2048 目标和失败使用遮罩。
  - 方向键、Xbox D-pad/左摇杆、A 暂停/开始、Start 暂停，Back/Home 仍由系统处理。
  - 有效移动播放分级音调；2048/失败使用 RGB 闪光和短震动反馈。
- `src/services/Game2048ProfileService.*`：独立 `pgos_2048` NVS 资料。
  - 保存最佳分、最高方块、完成局数和达成 2048 的局数。
  - 不复用 16 位 `GameScoreService`，避免高分截断。
- Games 菜单新增 `2048`，USB/TCP 支持 `page 2048` / `game 2048`，USB 控制台快捷键为 `E`。

## 真机结果

2026-07-24 用户在 COM3 烧录版本上完成首轮体验，Games 入口、开局、方向移动和基础动画未报告异常，本轮可提交。该结论是初步操作验收，不替代达成 2048、满盘判负、重启持久化及长局稳定性的专项测试。

## 待真机验收

1. 从 Games → 2048 进入，确认标题、空盘遮罩、分数卡片和首局生成两个方块。
2. 用 D-pad 及左摇杆连续完成四方向移动，确认单次输入不会重复移动；确认息屏后的首次输入只唤醒屏幕。
3. 观察普通滑动、两块合并、四块双合并、边缘压缩和新块弹出动画；确认合并动画结束不会跳格或留下残影。
4. 通过 USB 测试盘面后验证 2048 目标提示仍可继续移动；填满无可合并盘面后确认失败遮罩锁定输入，A 可重新开始。
5. 开启 RGB/声音/手柄时检查合并、2048、失败反馈；关闭 RGB 后应无灯光输出。
6. 重启设备确认 `pgos_2048` 的最佳分、最高方块和统计持久化；中途 Back/Home 退出后最佳分仍应保存。

## 资源预算

规则引擎约 4KB Flash、不到 1KB RAM；App 状态约 2KB RAM，未申请 PSRAM framebuffer。动画只保存 16 条固定长度 motion 记录，动态过程不写 NVS，资料只在局结束或退出时写入。
