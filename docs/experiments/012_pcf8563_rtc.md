# 实验 012：PCF8563 I²C 实时时钟

## 目标

在不改变 ES8311 音频方向的前提下，把用户接入的带电池/晶振 PCF8563 模块加入 PGOS，并提供一个可观察的本地时间页面。RTC 是可选硬件：模块缺失、NACK、VL 置位或字段非法时，显示、音频、Wi-Fi 和 USB 仍应继续工作。

## 器件和寄存器依据

- 原始资料：工作区本地参考文件 `docs/datasheets/PCF8563.pdf`（按项目纪律不纳入 Git）；本实验使用寄存器概述、Control_status_1、VL_seconds、时间寄存器和“设置/读取时间”章节。
- 7-bit I²C 地址：`0x51`（写地址 `0xA2`、读地址 `0xA3`）。
- 控制寄存器 `0x00` 的 STOP 为 bit 5；时间寄存器为 `0x02`～`0x08`。
- 秒寄存器 `0x02` 的 VL 为 bit 7；VL 置位时资料明确表示不能保证时钟信息完整性。
- 读写时间时一次完成秒到年的连续访问，避免跨多次访问产生不一致的日历快照。

## 固件实现

- `I2cBusService` 统一初始化 GPIO16/SDA、GPIO15/SCL、400 kHz `Wire`；ES8311 和 PCF8563 只使用自己的地址。
- `TimeService` 每秒读取一次；未发现模块时 5 秒重试，I²C 读错误时 2 秒重试。
- 启动时不自动把编译时间写入 RTC。首次使用通过 USB 设置真实本地时间：

  ```text
  time set 2026-07-19 15:30:00
  ```

- 设置时间时先写 STOP，随后一次写入 `0x02`～`0x08`，最后清除 STOP；当前项目支持 2000～2099，并写入 `C=0`。
- `Time` 页面显示 HH:MM:SS、日期、星期、PCF8563 状态和设置命令提示。页面会区分 `ready`、`not_found`、`voltage_low`、`stopped`、`invalid` 和 I²C 错误。
- Wi-Fi 进入 `connected` 后自动启动 SNTP，服务器为 `pool.ntp.org`、`time.nist.gov`、`time.google.com`，时区为 `CST-8`（UTC+8，无夏令时）。收到有效网络时间后自动写回 PCF8563；每 6 小时允许一次新的网络校对。没有 RTC 时系统仍会获得 SNTP 时间，但状态栏只显示可信 RTC 的 `HH:MM`。
- 系统状态栏右上角显示有效时间源的 `HH:MM`；回退顺序为本次开机已完成的 NTP、PCF8563 `ready`、`--:--`。Time 页面显示同一有效源的完整日期时间，同时单独报告 PCF8563 状态。
- 诊断命令：`page time`、`time status`、`i2c scan`、`status`（后者包含时间服务状态）。`time status` 还会报告 `ntp=off|pending|synced`、`ntp_syncs` 等校时状态。

## 首次真机验证（2026-07-19）

- COM3 构建、烧录和镜像校验通过；显示、ES8311、RGB、Wi-Fi 和 USB 控制台正常启动。
- 共享 I²C 初始化为 SDA GPIO16 / SCL GPIO15 / 400 kHz，ES8311 报告 ready。
- 首次启动时 `i2c scan` 只发现 `0x18`，设备数为 1；PCF8563 预期地址 `0x51` 没有 ACK，`time status` 为 `state=not_found`。
- Wi-Fi 连接到既有网络，SNTP 请求和网络时间接收成功；即使 RTC 未被探测到，状态栏和 Time 页面也能通过 NTP 回退显示时间。稳定截图保留在本地 `captures/playground-20260719-103617.png`。
- 随后在运行中复测/重新接触模块后，TimeService 的低频重试自动恢复：`state=ready rtc=pcf8563 address=0x51 detected=yes vl=0 stop=0 reads=23 errors=0 ntp=synced source=ntp`。这确认了 PCF8563 地址、连续读取、VL/STOP 校验和 NTP 回写路径。
- 稳定截图保留在本地 `captures/playground-20260719-104429.png` 和 `captures/playground-20260719-104431.png`。
- 手压插座进行不稳定接触测试时，实测日志出现 `ready → io_error → ready`：读取错误计数从 0 增加到 1，随后重新探测成功；期间 NTP 时间继续有效，未阻塞 UI/Wi-Fi/音频，也没有高频日志刷屏。
- 当前结论：总线通信、NTP 回退、NTP 回写、运行中恢复、接触不稳定降级和 Time 页面滚动均已真机通过；电池断电保持、冷启动无网络时的 RTC source，以及长期漂移仍待单独记录。

## 冷启动验证（2026-07-19）

- 保持模块接触并通过 USB 复位后，启动阶段第一次 RTC 读取即为 `state=ready rtc=pcf8563 address=0x51 detected=yes vl=0 stop=0 errors=0`。
- `i2c scan` 发现 `0x18`（ES8311）和 `0x51`（PCF8563），设备数为 2。
- 在 Wi-Fi/SNTP 完成前，周期状态已显示 `source=rtc local=2026-07-19 10:47:00`；随后 SNTP 收到网络时间并打印 `PCF8563 local time updated`，后续状态切换为 `source=ntp`。
- 因此“开机先用 RTC、联网后校准并回写、无 RTC 时 NTP 回退”的路径已通过真机验证；剩余只需焊接后做电池断电保持和长期漂移记录。

## 后续真机检查

1. 确认 VCC 为 3.3 V 兼容、共地，且模块上拉和 ES8311 上拉没有造成异常低阻值。
2. 启动后执行 `time status`，记录 `state=ready`、`vl=0`、`stop=0` 和首次读出的时间；若为 `not_found`，先检查地址、SDA/SCL 方向和电源。
3. 执行 `time set YYYY-MM-DD HH:MM:SS`，观察页面秒计数连续增加；断电后再次启动，确认电池保持时间。
4. 配置 Wi-Fi 后观察日志中的 `[time] NTP time received`，确认 `ntp_syncs` 增加且 RTC 时间被更新；断网后确认状态栏仍由 RTC 保持。
5. 若出现 `voltage_low`，先不要把显示值当作可信时间，检查电池、电源和模块充电回路；真实结果回填本实验，不只保留在聊天记录中。
